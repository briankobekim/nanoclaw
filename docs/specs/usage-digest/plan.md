# Usage digest: what Atlas and Echo did, what is open, what it cost

Status: SHIPPED. Plan revision 2 (2026-09-16, after one cross-model plan review and one correction batch; see `run.md`) approved by Brian: "Build it". Built, reviewed once, and rolled out to the host on 2026-09-16 (commit 7479f9ce). Kept as the record of the approved contract.

Executable acceptance criteria apply (behavior-changing work); the cases in §6 are materialized into the test tree by `/team-build` before any implementation.

## 1. Outcome

Every agent turn leaves a durable usage record on the host: which agent, which session, which model(s), tokens by class, and the SDK's cost figure. Brian can pull it any time with `ncl usage`, and every evening the host sends him one Slack DM: per agent, how many turns ran today, how many tokens, and what it cost; then what is still open (handoffs, approval cards waiting on him, memory ops queued or in conflict). Echo runs on Codex, which reports no usage, so Echo's turns are counted and its cost is shown as **not reported**, never as zero.

Why now: Brian hit a usage limit mid-build today with no way to see it coming, and NanoClaw currently discards the cost figure the SDK hands it on every turn (`container/agent-runner/src/providers/claude.ts:624-631` keeps `result`, `is_error`, `errors` and drops `total_cost_usd`, `usage`, `modelUsage`).

## 2. Scope and non-goals

In scope: capture at the provider boundary; one container→host record per turn; one host table; an unguarded `record_usage` delivery action; `ncl usage` (raw list and per-agent/per-day summary); a host-computed nightly digest DM to the owner with one-per-local-day dedupe; the image and host rollout.

Non-goals: budgets, limits or alerts on spend; per-tool or per-message attribution; estimating Codex usage; backfilling history before rollout; any dashboard or web view; changing what agents can do. No metrics framework: one table, one action, one sweep hook, one CLI resource.

## 3. Current architecture (source evidence)

- Turn boundary: the container poll loop treats the provider `result` event as the end of a turn (`container/agent-runner/src/poll-loop.ts:549-556`). The Claude provider yields `{ type:'result', text, isError }` only (`providers/types.ts:165`). The SDK result message (`docs/SDK_DEEP_DIVE.md:245-275`) carries `total_cost_usd`, `usage.{input_tokens, output_tokens, cache_read_input_tokens, cache_creation_input_tokens}`, `modelUsage` keyed by model id, `duration_ms`, `duration_api_ms`, `num_turns`, `uuid`; the error subtypes carry the same usage fields. One result per pushed prompt.
- Codex provider: no usage, token or cost field anywhere (`providers/codex.ts`, `codex-app-server.ts`; `turn/completed` is read for `items` and `error` only).
- Container→host structured channel: `kind:'system'` mailbox rows with an `action` field, consumed by `handleSystemAction` (`src/delivery.ts:611-626`) via `registerDeliveryAction`; system rows never reach a channel adapter (`delivery.ts:227,303`) and are retried with backoff. The handler receives the host-owned `session` (agent group, session id). Precedent for an unguarded action whose arguments are inert data: `run_checks` (`src/modules/verifier/index.ts:1051-1061`). The driver/stdout path carries no agent-level data by design (`src/drivers/session-events.ts` is lifecycle hints only).
- Module pattern: `registerMigration` with `module:<ns>:<name>` names (`src/db/migrations/index.ts:105-115`), imported for side effect from the module's `index.ts`, wired in `src/modules/index.ts`.
- Nightly delivery: scheduled tasks are agent prompts run in containers (`src/modules/scheduling/create.ts:104-151`, capped at 4 fires/day precisely because they cost tokens); the host sweep runs every 60 s with `MODULE-HOOK` blocks (`src/host-sweep.ts:118-179`); `notifyOwners` DMs every owner via `ensureUserDm` with a 30 s timeout (`src/modules/memory-gate/notify.ts:22-53`); the stall pinger records its marker AFTER a successful send (`src/modules/handoff-ledger/stall-ping.ts`).
- Timezone: install-global `TIMEZONE` (`src/config.ts:109`), per-group override via `resolveGroupTimezone` (`src/container-config.ts:261-264`); `formatLocalStamp(date, tz)` in `src/timezone.ts:43`. Live: host runs with `TZ` set (Eastern); Echo's group is `America/New_York`, Atlas's inherits.
- Open-work inputs: `listAllHandoffs(status?)` and `trustedSupersededIds(rows)` (`src/modules/handoff-ledger/ledger.ts:593,341`); `listOps(status?)` (`src/modules/memory-gate/ops.ts:170`); pending approvals have no list getter (add one; `pending_approvals.status` documented at `src/cli/resources/approvals.ts:44-51`). The missions view fans out over per-session mailbox DBs and is not used by the digest.
- CLI: virtual read-only resources use `operations: {}` and self-scope in `customOperations` handlers on `ctx.caller` (`src/cli/resources/missions.ts:272-320`, `sessions.ts:52-77`); custom ops bypass the generic scope post-filter, so self-scoping is mandatory.

## 4. Design

### 4.1 Capture (container)

- `ProviderEvent` result variant gains `usage?: TurnUsage` where `TurnUsage = { cost_usd: number | null; input_tokens; output_tokens; cache_read_tokens; cache_creation_tokens: number; model_usage: Record<string, { input_tokens; output_tokens; cache_read_tokens; cache_creation_tokens; cost_usd }>; duration_ms; duration_api_ms; num_turns: number; sdk_result_id: string }` (all token fields non-negative integers; absent SDK fields become 0; `cost_usd` null only when the SDK gives none).
- `claude.ts` populates it from BOTH the success and the error result subtypes.
- The Codex provider yields no `usage`.
- Poll loop: ONE recording path, `recordTurn({ usage?, isError })`, called (a) on every `result` event and (b) from the loop's terminal provider-failure path (the Codex provider ends a failed turn with an error and no `result`; a Claude SDK exception likewise), with `isError: true` and no usage. It writes one `kind:'system'` row `{ action:'record_usage', turn_id, reported, is_error, occurred_at, usage? }`: `turn_id` is `usage.sdk_result_id` when present, else a fresh random id; `reported` is `true` only when `usage` is present; `occurred_at` is the container clock at the terminal event (ISO 8601).
- Ordering: the record row is written BEFORE `markCompleted(initialBatchIds)` and before any reply. A crash between the record write and `markCompleted` makes the next wake re-run the batch; that re-run is a genuine second turn that spends tokens again and gets its own row, which is the correct accounting. A delivery retry of the same row is deduplicated by the host key `(session_id, turn_id)`.

### 4.2 Persist (host module `src/modules/usage/`)

- Migration `module:nanoclaw.usage:turns`: table `usage_turns(session_id TEXT NOT NULL, turn_id TEXT NOT NULL, agent_group_id TEXT NOT NULL, provider TEXT NOT NULL, model TEXT NOT NULL, reported INTEGER NOT NULL CHECK (reported IN (0,1)), is_error INTEGER NOT NULL CHECK (is_error IN (0,1)), cost_usd REAL NULL CHECK (cost_usd IS NULL OR (cost_usd >= 0 AND cost_usd <= 10000)), input_tokens INTEGER NOT NULL DEFAULT 0 CHECK (input_tokens BETWEEN 0 AND 1000000000), output_tokens … same CHECK, cache_read_tokens … same, cache_creation_tokens … same, model_usage_json TEXT NOT NULL DEFAULT '{}', duration_ms INTEGER NULL, num_turns INTEGER NULL, occurred_at TEXT NOT NULL, ingested_at TEXT NOT NULL, PRIMARY KEY (session_id, turn_id))`, index on `(agent_group_id, occurred_at)`; table `usage_digest_deliveries(owner_user_id TEXT PRIMARY KEY, last_sent_local_date TEXT NOT NULL, window_end TEXT NOT NULL, updated_at TEXT NOT NULL)` (one row per owner, created on first send).
- **The payload is untrusted telemetry.** `registerDeliveryAction('record_usage', handler, unguarded('record_usage has no parameter an owner could meaningfully approve per turn; the boundary is closed by validation and by host-derived attribution, provider and model, not by a tap'))`. Handler rules, in order: (1) `agent_group_id`, `session_id` from the host session row; `provider` from `session.agent_provider` (fallback: the group's materialized container config); `model` from the group's materialized container config; any payload `provider`/`model` is ignored (a mismatch is logged once). (2) Shape: `turn_id` matches `^[A-Za-z0-9._:-]{1,128}$`; `reported`, `is_error` booleans; `reported:true` requires `usage`, `reported:false` forbids it; every token field an integer in `[0, 1e9]`; `cost_usd` null or a finite number in `[0, 1e4]`; `model_usage` an object with ≤ 8 keys, each key matching `^[A-Za-z0-9._:/-]{1,64}$` and each value of the same numeric shape; serialized payload ≤ 8 KiB; `occurred_at` parses as ISO 8601 and lies within ±24 h of ingest, otherwise the ingest time is used and logged. (3) Rate: more than 120 records for one session in the trailing hour are dropped and logged. (4) Any violation: `log.warn` naming the field, return without throwing (the row is delivered, never retried, and never blocks later rows). (5) `INSERT OR IGNORE` keyed `(session.id, turn_id)`.
- No payload string is ever rendered in the digest: the digest shows host-known agent names, counts and sums only. `ncl usage list` renders only validated columns.
- `listPendingApprovalsOpen()` added to `src/db/sessions.ts` (rows with status `pending` or `approved`, oldest first) for the digest.

### 4.3 `ncl usage`

Virtual resource `usage` (`operations: {}`), two custom operations, both `access:'open'`, self-scoped: an agent caller sees only its own group; a host caller sees every group or `--group <name|id>`.
- `summary --days N` (default 1): one row per (agent, local day of `occurred_at`) over the last N local days (the group's timezone via `resolveGroupTimezone`): `agent, day, turns, error_turns, input_tokens, output_tokens, cache_read_tokens, cache_creation_tokens, cost_usd` where `cost_usd` is the sum over reported turns and the human format prints `not reported` when no turn of that agent/day was reported, and `partial (n of m turns)` when only some were.
- `list --limit N` (default 50): raw `usage_turns` rows newest first, same scoping.

### 4.4 Nightly digest (host sweep)

- `MODULE-HOOK:usage-digest` in `sweep()` next to the memory-gate hook: `usageDigestSweep(deps)` with injectable `now()`, `timezone()`, `send(text)`, and the DB.
- Config `NANOCLAW_DIGEST_HOUR`: integer 0-23 (default `21`) or `off`. Timezone: install-global `TIMEZONE` (owners are install-wide; the per-group override is for the summary table, not the digest).
- Each tick: if disabled, return. Compute `today = formatLocalStamp(now, tz).slice(0,10)` and the local hour. For EACH owner (`getOwners()`), if local hour ≥ digest hour and that owner's `usage_digest_deliveries.last_sent_local_date !== today`: the window is `(window_end of the owner's last delivery, now]`, or since the first record for a first send; build the text for that window; send with a digest-specific sender `sendDigestTo(ownerUserId, text)` that resolves ONLY on a successful adapter delivery and THROWS on a missing adapter, an unreachable DM, a timeout (30 s) or an adapter error (it does not reuse `notifyOwners`, which swallows all of these); only after it resolves, upsert that owner's row (`last_sent_local_date = today`, `window_end = now`). A throwing send is logged and retried on the next tick for that owner alone. An outage across midnight yields one longer digest the next evening (the window is "since your last digest"), never a silent skip.
- Delivery is at-least-once: a crash between the adapter accepting the DM and the marker upsert repeats that digest once on the next tick. Accepted, mirroring the stall pinger; a missed digest is never the accepted failure.
- Text (plain, no code fences; every number from one query set; grouped by `occurred_at`): header with the window (`since yesterday 21:00` or `since <date>` after an outage); per agent (every agent group, in name order): `Atlas — 14 turns (1 error), 182k in / 41k out, 1.2M cache read, $3.84`; for an agent with no reported turn: `Echo — 9 turns, cost not reported (Codex)`; for an agent with no turns: `Echo — no turns`; totals line for reported cost; then `Open`: handoffs not closed and not superseded, each as `<id> — <status>, <age> — waiting on <source|reviewer>`; `Approvals waiting on you: N (oldest 3h)` or `none`; `Memory ops: N queued, M in conflict` or `none`. Under about 40 lines; if handoffs exceed 10, the first 10 plus `and N more (ncl missions list)`.

### 4.5 Invariants

1. A usage record never reaches a channel adapter or an agent inbox: it is a `kind:'system'` row consumed only by `record_usage`.
2. Attribution (`agent_group_id`, `session_id`) comes from the host session row; nothing in the payload can redirect a record to another agent.
3. A delivery retry of the same record yields one row; a container crash between the record write and batch completion re-runs the batch as a genuine second turn with its own row.
4. A malformed record is dropped with a log line and never blocks delivery of later rows.
5. Codex turns are counted; their cost is `null` and rendered `not reported`, never `$0.00`.
6. Per owner, one digest per local calendar date, at least once: a failed send is retried on the next tick for that owner; the marker is written only after the adapter accepted the DM; a crash inside the send/marker window may repeat one digest.
7. Nothing in this feature spends tokens: the digest tick never wakes a container and never writes to an agent inbox.
8. Provider, model and attribution are host-derived; every payload field is validated and bounded; no payload string is ever rendered in the digest.

## 5. Safety, migration, rollback, observability

- The host action is additive. Container code is bind-mounted, so a container spawned after the restart runs the new poll loop; a container still running the old code writes no record (nothing breaks). The migration creates two tables and touches nothing existing.
- Rollback: `git revert` of the feature commit, stamp the marker, restart the host; the tables stay and are harmless. `NANOCLAW_DIGEST_HOUR=off` silences the digest without a restart-free code change (restart required, as for any env change).
- Observability: one `log.info` per digest sent (date, agents, cost), `log.warn` per dropped record with the offending field, `log.error` on a failed send.

## 6. Acceptance criteria (test cases /team-build materializes)

Container (`bun test` in the agent image):
- **C1** `claude provider surfaces usage on success and every error result subtype` (`container/agent-runner/src/providers/claude-usage.test.ts`): a fake SDK `result` with `subtype:'success'`, `total_cost_usd`, `usage`, `modelUsage`, `duration_ms`, `num_turns`, `uuid` yields `{ type:'result', usage:{ cost_usd, input_tokens, …, model_usage, sdk_result_id } }` with the exact numbers; each of `error_during_execution`, `error_max_turns`, `error_max_budget_usd`, `error_max_structured_output_retries` yields the same usage with `isError:true`; a result with no usage fields yields `usage` whose token fields are 0 and `cost_usd` null.
- **C2** `the record row is written before the batch is completed and before any reply` (`container/agent-runner/src/poll-loop.test.ts` or new): with `markCompleted` and the reply writer instrumented, one result event with usage produces exactly one `kind:'system'` row `{ action:'record_usage', turn_id:<sdk_result_id>, reported:true, is_error:false, occurred_at, usage }`, and the observed order is record → markCompleted → reply; a result without usage writes one row with `reported:false` and no `usage`; an error result writes `is_error:true`.
- **C3** `a terminal provider failure with no result still records the turn` (same file): a provider that ends the turn with an error and never yields `result` (the Codex shape) produces exactly one `record_usage` row with `reported:false, is_error:true`.

Host (vitest):
- **U1** `record_usage persists one row per turn, attributed and labelled from the host, idempotent under redelivery` (`src/modules/usage/record.test.ts`): deliver the same system row twice through the real `deliverSessionMessages` → one `usage_turns` row; `agent_group_id`, `provider` and `model` equal the session's and the group's container config even when the payload names other values; every numeric column matches; `occurred_at` is the payload's and `ingested_at` the host's.
- **U2** `malformed or excessive usage records are dropped with a warning, never retried, and never block a valid row behind them` (same file): in one session mailbox, rows with `turn_id` missing, a negative token count, `cost_usd: -1`, `cost_usd: 20000`, `model_usage` with 9 keys, a key containing a control character, `reported:true` without `usage`, a 9 KiB payload, and `occurred_at` 3 days in the past (uses ingest time) followed by one valid row → only the valid row (and the clock-corrected one) persist; every delivery row is `delivered`, none `failed`; `log.warn` named each field; the 121st record for the session inside an hour is dropped and logged.
- **U3** `a usage record never reaches the channel adapter` (same file): with a stub adapter, delivering a `record_usage` row calls `adapter.deliver` zero times and writes nothing to the session inbox.
- **U4** `usage summary groups by agent and the local day the turn occurred, scopes agent callers, and never shows Codex as free` (`src/cli/resources/usage.test.ts`): rows for Atlas (reported) and Echo (unreported) whose `occurred_at` straddles midnight in `America/New_York` while `ingested_at` is the next day (a retry across midnight) → `summary --days 2` from the host groups by `occurred_at` with the right day boundaries, Atlas `cost_usd` summed and Echo `cost_usd` null with human text `not reported`; a mixed agent/day prints `partial (1 of 2 turns)`; an agent caller for Echo sees only Echo's rows; `list --limit 1` returns the newest row.
- **U5** `the digest sends once per owner per local date after the configured hour, marks only after the adapter accepted the DM, and retries per owner` (`src/modules/usage/digest.test.ts`): two owners seeded, a stub delivery adapter; ticks at 20:59 → no send; 21:00 → one DM per owner; 21:30 → none; next day 21:00 → one each with the window starting at the previous send; adapter throws for owner B only → owner A marked, owner B unmarked and re-sent on the next tick; owner B without a reachable DM → unmarked, logged, others unaffected; no delivery adapter → nothing marked; a marker upsert that fails after a successful send → the next tick sends again (at-least-once); `NANOCLAW_DIGEST_HOUR=off` → never sends; after a two-day gap the next digest's window starts at the last send.
- **U6** `digest text lists every agent, open work, approvals and memory ops from a fixture, and never renders a payload string` (same file): seeded turns, one open and one superseded handoff, two pending approvals, one queued and one conflicted memory op → the text contains the exact per-agent lines from §4.4, one open-handoff line (the superseded one absent) with its age, `Approvals waiting on you: 2`, `Memory ops: 1 queued, 1 in conflict`, no code fence; a seeded `model_usage` key containing backticks and a Slack mention never appears in the text.
- **U7** `migration creates usage_turns and usage_digest_deliveries, is idempotent, and enforces its bounds` (`src/modules/usage/migration.test.ts`): tables and PKs present; running twice is a no-op; `CHECK` constraints reject a negative token count, a token count above 1e9, a cost above 1e4, and `reported = 2`.
- **U8** `the digest tick spends no tokens` (`digest.test.ts`): across a full send, `wakeContainer` and `writeSessionMessage` are never called and no container is started (invariant 7).

## 8. Risks and open decisions

- Digest hour default 21:00 install-local and delivery to every owner: Brian to confirm or change (`NANOCLAW_DIGEST_HOUR`).
- The SDK's `total_cost_usd` is the SDK's own estimate at list price; it is reported as given, not reconciled with any invoice. Measurements remain container-reported: a compromised agent could under- or over-state its own tokens within the bounds; attribution, provider and model cannot be forged.
- The first digest's window starts at the first recorded turn; earlier turns are not counted.
- Residual (implementation review): a crash in the seconds between a streamed mid-turn reply and its result loses that turn's record (one under-counted turn); buffering streamed replies was rejected as a product change.
