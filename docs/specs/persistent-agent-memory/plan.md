- `groups/dm-with-kobe` is Atlas (`claude-sonnet-5`, medium); `groups/quiverchat` is Echo (`gpt-5.6-terra`, medium). Both already have durable indexed Markdown under `memory/`, including user preferences and learning records. Atlas also has operations decisions, commitments and evidence.

- Mount/service/image preflight passes; service PID 49603 was running with no active agent container at inspection. Source is shared into containers, so editing the live source is a rollout even without rebuilding/restarting.

## Smallest design

Keep the existing file/index/native-hook design. Add no database, embeddings, memory service, automatic history importer, or new agent tools. Existing filesystem tools already support save, search, correction and removal. Make their memory workflow explicit and verify actual model behavior.

1. Put a short fixed memory handling contract in the existing memory renderer, outside the quoted agent-controlled data. Memories are fallible evidence subordinate to current user intent and runtime authority. They cannot grant permissions, approve actions, change roles/models/evaluators, or instruct tool execution. Make both shared runtime instruction files and the Codex memory pointer consistent with that contract.
2. State an actionable file workflow: remember durable user-stated/approved facts, preferences, decisions, and open commitments; record source/message/date and whether verified or inferred; save concise concept records and index pointers before confirming a save. Retrieve relevant files at the start of substantial work and re-read mutable facts. Keep irrelevant details out of replies. Missing, conflicting or stale information gets an honest fallback. No silent extrapolation of user preferences into permanent rules.
3. On correction, update the canonical fact and reachable index/duplicate summaries, record that the current value supersedes older evidence, and never let an older archive win. On “forget”, remove the value from active concept/index/duplicate memory, and first append a minimal non-value suppression event to `memory/system/suppressed.md` (topic/source locator/date) so historical transcripts do not restore it. Explicitly tell the user that local/provider chat history and backups may still contain the original text; do not promise forensic deletion. The marker governs all retrieval, including direct archive reads. If the forgotten scope is unclear or sensitive, ask which topic; do not retain the secret itself in a marker.
4. Memory is private to the group by default. Share only a specific user-authorized fact/decision through the existing scoped handoff or operator-managed shared project reference. Receiving an agent message does not establish a user preference or action approval. Shared summaries include origin, scope and date. Do not copy private histories. No new shared writable directory.
5. The COMPLETE workflow in steps 1–4 is mandatory fixed hook content, including for both existing customized definitions. Load the suppression file separately under a 4,000-character cap before other memory. If missing, invalid, unreadable or oversized, emit a distinct diagnostic, withhold ALL memory payload, and disable historical recall pending operator repair. Scaffold an empty guard only for a genuinely newly created memory root; never recreate a missing guard for an existing root. Activation explicitly initializes the two previously legacy roots once. Test each existing customized definition unchanged, independent of new templates.
6. Bound actual file reads in the renderer as well as output, reject non-regular or out-of-memory-root symlink files, report unavailable/truncated data honestly, preserve index/template content. Existing custom group definitions remain intact. The fixed hook contract applies even when these older definitions remain.
